# Astra 聚焦独立审计与下一步研究决策：v29–v32

## 一、结论与明确方向

**下一项科学实验应是：在已打开的分支状态上，交叉控制 horizon 与 terminal value，识别 v29 的救援和成本异常究竟来自 H、terminal，还是求解局部解。暂不启动新的 selector 梯度训练，不直接验证 v32，也不把 source242 删除为“不可行场景”。**

理由如下：

1. **v29 已否定“source242 在当前模型下必然不可行”**：`H35 + V35` 能完成两个分支；H12/H15/H25 的失败主要表现为达到步数上限，而非已记录的碰撞或 solver failure。
2. **v29 尚未证明“必须使用 H35”**：H35 同时换用了 `V35`，而 H12/H15 使用 `V15`。这是 controller configuration 的有效救援证据，不是纯 horizon 因果证据。
3. **v32 确实推翻了“当前特征完全没有可分信号”的强说法**，但其核心特征 `abs_obs_07` 实际是 **第一个障碍物的半径 `obj_0_r`**，不是动态风险或历史变量。五个 source-family 上的事后稳定性，不能区分真正的几何规律与静态 source fingerprint。
4. **v32 残留的 `v19_c13` 是成本异常，不是碰撞或未完成任务**。优先解决 `H35 + V35` 为什么在相邻分支中产生明显成本劣化，比直接采集更多“H15 类标签”更有因果信息价值。
5. **v31 的缺类解释不是全部原因**：改变默认动作后，LOGO bad 从 5 降至 1，说明默认动作、模型类与小样本覆盖共同作用；不能把“每类只有一个 family”当成已经排他确认的失败原因。

研究顺序因此冻结为：

> **terminal × H 因果拆分 → 新 source 的前瞻性机制确认 → 条件满足后进行真实闭环与全决策计时。**
