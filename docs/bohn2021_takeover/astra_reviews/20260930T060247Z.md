### 任务 2：执行 24 次固定上下文 solver probe，分离 objective 与 basin
**稳定 ID：`A11`、`A6`**

这是下一项新增科学实验。完成任务 1 的基本一致性与备份核验后实施。

**冻结设计**

| context | H | terminal | initialization |
|---|---|---|---|
| source242 slot0，原 branch step52 起点 | 15、35 | zero、V15、V35 | canonical、一个确定性 goal-facing guess |
| c13：`exec33046…/trace.jsonl` 第2行的 `previous_state`，对应原 step46 | 12、35 | zero、V15、V35 | 同上 |

合计：**24 solver calls、0 plant steps、0 training updates、0 selector refits**。

不得按结果增加第三种 guess、补抽状态或增加 continuation。使用低层求解接口；若调用现成 `env.reset` 会触发 warmup 求解或 plant step，必须避免，不能把隐藏 warmup 排除后仍宣称零 plant steps。

**实现要求**

- 同 context、同 H 的各 terminal arm，仅允许 terminal weights/biases 不同。
- 保存完整 `opt_p`、forecast/TVP、goal、previous input、bounds、primal 初值及实际 solver 输入。
- source242 起点保持 v33 的 reset previous-input 契约；c13 step46 使用所选 trace 的前一步 input，所有 arms 一致。
- goal-facing guess 的规则在执行前固定，按最短角误差构造有界转向和速度序列；不根据单元结果修订。
- 保存完整解，不再只保存 warm-start 前若干元素。
- 分解 discounted stage、slack、regularization、`γ^H V`，重构总 objective。
- 在相同 H/context 下，对取得的全部可行解做 **同目标交叉评价**。不要比较不同 V/H 的原始 objective 大小来判断优劣。

**数值门与可证伪判据**

- objective 重构误差：  
  `≤ 1e-6 × max(1, |J|)`；
- feasibility 沿用现有 residual 门，不放宽；
- 同一 objective 下，预先定义显著改善为  
  `ΔJ > 1e-4 × max(1, |Jcanonical|)`，同时报告动作和预测轨迹是否改变。

分流：

1. **参数/重构失败**：支持 contract 问题，停止科学归因，先做工程修复。
2. **alternate 或交叉得到的可行解明显降低同一 J**：支持原求解落入较差 basin。
3. **不同初始化稳定选择相同方向，且 learned objective 对低 physical-cost 候选反而评分更差**：支持 objective/value 偏好失配；仍不等于已经证明 Bellman target 错误。
4. **c13 的共同 cold-start probe 不复现原方向差异**：不得称为已经解释 v33；应记录它没有复现原轨迹的 warm-start 上下文，本轮不追加求解。
5. 两种 guesses 都失败或无差异：如实回传，不转成“短 H 不可行”或“全局最优”结论。

**执行后立即触发因果结果回传。** 本轮不自动接续 selector training 或新 source acquisition。

## 七、仍需更大科学选择的事项与最终限制

下一项机制证据出来后，才决定：

- 修复实现，还是改初始化/recovery；
- 重训 terminal，还是改用 goal-relative、周期性或更充分的表示；
- shared terminal 与 per-H matched-terminal 的训练、选择预算如何公平分配；
- 是否仍需要三类 selector，还是更简单的 H12/H35 或强固定配置已足够。

任何正式 retraining 路线仍须冻结 train/selection/independent confirmation，至少 **三个独立 training seeds**，并给 fixed-H 基线公平的 terminal 与调参机会。不能在这六个状态上拟合后称为独立确认。

本轮计时只支持诊断：runner 计时包围 `controller.get_action`，`selection_s=0`；有 state 内随机顺序和 CPU telemetry，但没有重复配对的在线 switching 测量。  
证据：`E33:251–258`；`experiments/bohn2021_aws/vehicle_true_variable_horizon_case5_smoke_v0_runner.py:737–780`。抽查 CPU 样本存在约 `0.75–1.50%` steal，不能据此断言全部计时失效，也不能据单次时间排序宣称部署加速。

**明确遗漏：**

- 未逐行核验全部72条轨迹、所有失败末态和所有运行期参数；
- 未读取实际 terminal 数组内容、完整预测解、training replay 或 loss 曲线；
- 未完成全程 CPU 干扰与配对 timing 分析；
- 未重新审计完整 ORIGINAL 或 pendulum 恢复；
- 未下载验证外部备份资产；
- 未核验收尾时所有状态文件是否同步。

这是并发维护工作区的**非原子快照**，以逐文件读取哈希为证；不是统一 commit 的全量封存验收。**本报告是 development-only 的因果复核与执行建议，不是最终成功判定，也不授权打开 sealed test、改变研究目标或降低成功标准。**
