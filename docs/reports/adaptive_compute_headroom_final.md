# 最后一次预算分配收益诊断：停止当前研究方向

日期：2026-09-07。结论：**NO-GO，停止将 Model-Reliability-Aware Compute Allocation for MPPI 作为当前论文主线继续推进。**

这是资源投入决策，不是对所有任务、平台和预算策略的数学否定。此次没有把弱阳性写成零收益，也没有修改失败阈值。

## 1. 问题与冻结规则

前一阶段 PPO 没有达到继续标准。本次先绕开学习器，问：如果知道一个状态下各预算的开发分支结果，能否选出在另一次规划采样中仍然显著更好的预算？

运行前在本地提交 `a62ef76` 冻结了[协议](../protocols/adaptive_compute_final_headroom.md)及脚本。使用现有 Easy/Medium × lower/higher-error 四个条件，全都采用同一冻结 ICODE 校正、同一任务奖励、约束和当前真实状态观测设置。后者是已声明的机制隔离条件，不是未来信息。没有修改场景难度、成功阈值、模型 checkpoint 或 reward。

- 每个条件沿 fixed K128/H20、seed0 参考历史，在第0/30/60步取状态，共12个。
- 每个状态测试 K32/128/256 × H10/20/40，共9种预算。
- 每条分支保持预算60个控制周期（6秒），正常终止则提前结束。
- 两个规划噪声种子7、19，随机串行执行顺序种子290907。
- 每次重放完整参考历史，检查 MuJoCo integration state、PI/执行器延迟、MPPI sequence/action/RNG 的一致指纹；保存12个物理快照。没有只恢复位姿而遗漏隐藏状态。
- 用种子7挑选每个状态的预算，种子19评分；反向再做一次。固定参照也只在选择侧挑选一个全局预算。
- 收益为原任务奖励减实际 wall-clock penalty，beta=1、eta=1、gamma=.99，与上一轮 price1 开发 screen 相同。

继续标准：平均折扣收益提高至少 max(0.5, 10% × |固定参照收益|)，至少60%状态平均增益为正，无额外碰撞，平均前进距离不低于固定参照95%。只有通过才做 causal-feature ridge 输入诊断，再决定是否允许闭环学习验证。

## 2. 完成情况

完成全部216条分支、10,681个分支控制周期和6,480个参考历史重放周期。全部同状态恢复指纹检查通过，216条唯一分支完整；所有周期奖励从原始字段重新计算一致，误差为0。协议、配置和所有使用的 checkpoint 哈希核验通过。

输出目录：`research_artifacts/adaptive_compute_headroom_2026-09-07/`。包含冻结协议/manifest/resolved YAML、执行顺序、状态和物理快照、逐周期 JSON、summary CSV/JSON、判定 JSON、审计和图片 PNG/PDF/SVG。

## 3. 主要结果

以下是12个状态 × 两个评分方向的描述性均值。24个选中分支不是24个独立场景或完整 episode，不报告显著性或置信区间。

| 指标 | 跨采样选择的固定参照 | 跨采样状态选择器 | 差异 |
|---|---:|---:|---:|
| 平均折扣 task–latency 收益 | 51.2517 | 52.5062 | +2.45% |
| 平均分支前进距离，m | 2.0590 | 2.1320 | +3.54% |
| 平均分支规划总耗时，s | 0.4263 | 0.3518 | −17.47% |
| 在分支截止前到达目标 | 13/24 | 13/24 | 相同 |
| 碰撞 | 0 | 0 | 相同 |

收益增量为 **1.2545**，冻结阈值为 **5.1252**，因此 utility gate 未通过；其他三个标准通过。按协议不进行 ridge 诊断、监督预训练、追加 PPO 或正式实验。

不能把耗时减少17.47%藏掉：这是真实的局部计算节省信号。它是分支内规划总时间，不是P95延迟改善，也不是已部署学习策略的成绩。选择器没有付出在线预测预算的成本；平均每个分支只省约74.5ms，分摊到约49个周期约1.5ms/周期，额外推理成本可能侵蚀该空间。此前 reliability provider 的耗时来自另一短 profile，不能直接作为本次端到端实测值相减。

## 4. 有何规律，是否值得联合 K/H 和 reliability？

24次选择中：

- 18次 `(32,10)`；
- 4次 `(32,20)`，均为 Medium 的起始状态，两个动力学条件都如此；
- 2次 `(128,10)`；
- 没有选择 K256 或 H40。

因此22/24次仍是最低 K=32。可以观察到一个小的、以 H 为主的场景/阶段信号，但没有形成值得维持复杂联合 K/H 学习系统的充分证据。不能据此声称已经证明 H-only 与 KH 等价；本次没有正式训练比较两者。

平均增益在12个状态都为正，也不能解释为每个状态都需要自适应：选择侧种子7挑出的固定参照是 `(32,10)`，种子19挑出的是 `(32,20)`，两者自身存在选择噪声。很多状态在其中一个方向上选择器与固定参照完全相同，增益为0。

本次所有分支共享 ICODE dynamics，没有进行 scene-only vs scene+reliability 输入消融，因为前置收益 gate 已失败。因此本次不能独立归因 ICODE；之前其输入独立价值未建立的结论维持不变。

## 5. 选择偏差检查与局限

额外提供一个明确标为事后描述的乐观数值：直接在每次运行结果中挑最大收益，平均54.8742；同批数据选出的最好固定预算 `(32,20)` 平均52.9271，相差3.68%。这种同样本挑选与评分有乐观偏差，不是主判定，也不是所有可变预算策略的理论上界。它也未呈现很大的收益空间。

六秒分支的终点奖励会发生截止边界跳变。我们没有删除这些结果，且同时检查进展、碰撞和实际耗时。测试只覆盖两种几何、两种开发动力学条件、每条件一条参考历史及九个预算；不覆盖任意连续状态、候选范围中的所有整数 K/H、逐周期切换策略、GPU 平台或 Hard。Hard 在上一阶段缺少成功率分辨力，本轮未更改它来寻找阳性。

因此停止的依据是：**现有开发任务中，收益空间小且主要集中在少量 H 变化；此前 PPO 没有利用出优势；ICODE 输入的独立价值仍无证据。综合工程/训练成本，不继续投入当前论文主线。** 不能改写成“任何环境下 adaptive compute 都不可能有效”。
