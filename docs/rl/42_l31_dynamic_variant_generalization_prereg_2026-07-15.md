# L31 动态障碍泛化开发实验预注册（2026-07-15）

## 1. 研究问题

L30 已表明，基于 LaserScan 时序闭合速度的门控能够修复空间复杂度门控在单一横穿障碍场景中的失效。L31 不再调整门控阈值，而检验该结论能否推广到新的障碍运动方向、速度、尺寸和相遇时机。

本轮仍属于开发实验，不使用封存确认种子，不把结果表述为最终论文结论。

## 2. 冻结假设

主要假设：与仅使用空间门控相比，冻结的时间风险门控与 ICODE 组合模型在新的动态障碍变体中能提高成功率，同时不产生碰撞。

次要诊断假设：在相同时间门控和 RL prior 下，ICODE 对真实物理执行产生的模型失配具有非负净贡献；`temporal_gated_lcb_nominal` 仅作为动力学消融，不是安全候选控制器。

## 3. 实验设计

采用随机完全区组的配对重复测量设计：

- 独立模型区组：3 组独立 RL/ICODE 训练随机种子与 checkpoint；
- 区组内重复：5 个全新开发 episode seed；
- 动态场景：4 个；
- 物理域：2 个；
- 方法：5 个；
- 总计：$3\times5\times4\times2\times5=600$ 个 episode。

模型区组是主要独立重复单位；episode seed 是区组内重复测量；控制周期只用于形成轨迹指标，禁止当作独立样本做显著性检验。

### 3.1 动态场景

1. `anchor_standard`：L29/L30 的标准横穿场景；
2. `reverse_standard`：相同几何与速度，运动方向反转；
3. `fast_crossing`：障碍速度约从 $0.21\,\mathrm{m/s}$ 增至 $0.34\,\mathrm{m/s}$，并改变相遇相位；
4. `large_early`：半径由 $0.20\,\mathrm{m}$ 增至 $0.28\,\mathrm{m}$，采用不同速度与更早相遇相位。

所有障碍均为 MuJoCo 中参与接触和光线检测的实体。规划器只能通过 `LaserScan -> scan_guard -> local_obstacle_layer` 获得障碍信息，不能读取障碍真值轨迹。

### 3.2 物理域

- `nominal_seen`：训练/开发阶段既有物理参数；
- `combined_unseen`：质量、惯量、控制延迟、执行器和摩擦系数组合失配。

### 3.3 方法

- `traditional_icode`：传统 MPPI warm start + ICODE；
- `lcb_icode`：始终启用 RL prior + ICODE；
- `gated_lcb_icode`：空间复杂度门控 RL prior + ICODE；
- `temporal_gated_lcb_nominal`：时间风险门控 RL prior + nominal dynamics（诊断消融）；
- `temporal_gated_lcb_icode`：时间风险门控 RL prior + ICODE（主要候选）。

Memory 模块关闭，MPPI 样本数固定为 $K=100$。时间门控阈值从 L30 原样冻结：soft $0.05\,\mathrm{m/s}$、hard $0.20\,\mathrm{m/s}$、最大作用距离 $1.50\,\mathrm{m}$、保持时间 $0.60\,\mathrm{s}$。

## 4. 数据隔离

开发种子固定为 `20283101--20283105`。`20283106--20283120` 是新的封存确认种子，本轮禁止读取。L25--L30 的开发和封存 episode seed 均列入程序化保护集合，L31 不复用。

## 5. 预先定义的判定门槛

### 5.1 必须全部满足的完整性与安全条件

1. 600 个预期 episode 键完整、唯一，无额外条目；
2. 所有旧保护种子和 L31 封存种子均未使用；
3. 主要候选 `temporal_gated_lcb_icode` 的 120 个 episode 中碰撞数为 0；
4. 主要指标不存在 NaN、Inf 或无效记录。

### 5.2 效能条件（至少满足 3 项）

1. 主要候选总成功数不少于 108/120（90%）；
2. 8 个“场景 × 物理域”分层中，每层成功数均不少于 12/15（80%）；
3. 主要候选在至少 6/8 个分层中成功数最佳或并列最佳；
4. 相比 `gated_lcb_icode`，配对净成功增益不少于 24/120；
5. ICODE 相比同门控 nominal 的配对净成功增益非负，且净碰撞增量不大于 0。

只有完整性与安全条件全部通过，且效能条件至少 3 项通过，L31 开发门才通过。门通过也只允许提出后续封存确认，不会在本轮自动开启确认种子。

## 6. 报告与统计

- 按 8 个场景/物理域分层报告成功数、碰撞数和终点距离；
- 报告主要候选相对各基线的严格配对差值；
- 对终点距离差使用“模型区组 -> episode”两阶段 bootstrap 置信区间；
- 不将仿真 step 伪作独立样本，不把本开发轮的区间或 $p$ 值解释为确认性证据；
- 无论结果是否支持假设，均保留配置、运行顺序、checkpoint 哈希和原始轨迹。

## 7. 停止规则

若出现配置错误、缺失矩阵、checkpoint 不匹配、保护种子泄漏或数值异常，则停止结果解释并修复基础设施；若实验合法但门槛未通过，则记录为真实反证，不在同一批数据上重新调参后宣称通过。
