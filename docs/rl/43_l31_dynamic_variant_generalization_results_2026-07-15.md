# L31 动态障碍泛化开发实验结果（2026-07-15）

## 1. 结论先行

L31 开发门未通过。该结论不是由于数据缺失或运行故障：600/600 个预注册 episode 全部有效、唯一，3 个模型区组的 checkpoint seed 匹配，未使用任何旧保护种子或 L31 封存确认种子，也没有 NaN/Inf。

失败来自方法本身。主要候选 `temporal_gated_lcb_icode` 在 120 个配对 episode 中仅成功 64 次，并发生 56 次碰撞；预注册硬条件要求零碰撞，因此无需依赖其他指标即可判定失败。新的 `20283106--20283120` 确认种子保持封存。

这轮结果不否定“跨层置信度调控”这一研究问题，但明确否定了当前“用标量闭合速度直接增强 RL prior”的实现可以作为最终方法。L30 单一运动模式中的良好结果不能推广到新的速度、方向和相位。

## 2. 设计与数据完整性

- 3 个独立 RL/ICODE 模型区组；
- 5 个全新开发 episode seed；
- 4 个动态障碍变体；
- 2 个物理域；
- 5 种方法；
- 总计 $3\times5\times4\times2\times5=600$ 个 MuJoCo episode。

障碍是参与 MuJoCo 接触与 ray-cast 的实体。控制器仅经 `LaserScan -> scan_guard -> local_obstacle_layer` 感知障碍，没有读取动态障碍真值轨迹。Memory 关闭，MPPI 样本数固定为 $K=100$。

审计结果：

| 项目 | 结果 |
|---|---:|
| 预期 / 实际 episode | 600 / 600 |
| 缺失 / 重复 / 额外键 | 0 / 0 / 0 |
| 无效指标行 | 0 |
| checkpoint 区组不匹配 | 0 |
| 旧保护种子使用 | 0 |
| L31 封存种子使用 | 0 |

## 3. 预注册判定

### 3.1 硬条件

| 条件 | 结果 |
|---|---|
| 完整唯一矩阵 | 通过 |
| 保护与封存种子未使用 | 通过 |
| 指标有限且 checkpoint 正确 | 通过 |
| 主要候选零碰撞 | **失败：56/120 碰撞** |

### 3.2 效能条件

预注册要求 5 项至少通过 3 项，实际只通过 1 项：

| 条件 | 结果 |
|---|---|
| 总成功数至少 108/120 | 失败：64/120 |
| 每个分层至少 12/15 成功 | 失败 |
| 至少 6/8 分层成功数最佳或并列最佳 | 失败：4/8 |
| 相对空间门控净成功增益至少 24 | **通过：+28** |
| ICODE 不劣于相同门控的 nominal | 失败：成功 -5、碰撞 +5 |

因此正式判定为 `development_fail`。

## 4. 分层结果

主要候选在标准方向和“大尺寸/提前相遇”变体中仍较好，但在反向和快速横穿中失效：

| 动态变体 | 物理域 | 成功 | 碰撞 |
|---|---|---:|---:|
| Anchor | seen | 14/15 | 1/15 |
| Anchor | unseen | 15/15 | 0/15 |
| Reverse | seen | 1/15 | 14/15 |
| Reverse | unseen | 1/15 | 14/15 |
| Fast | seen | 2/15 | 13/15 |
| Fast | unseen | 5/15 | 10/15 |
| Large/early | seen | 13/15 | 2/15 |
| Large/early | unseen | 13/15 | 2/15 |

相对严格配对基线，主要候选的总体效应为：

| 比较对象 | 净成功增益 | 净碰撞增量 | 终点距离改善均值（95% 两阶段 bootstrap CI） |
|---|---:|---:|---:|
| Traditional MPPI + ICODE | +38 | -38 | $+0.826\,[0.579,1.074]$ m |
| Always-on RL prior + ICODE | +50 | 0 | $+1.117\,[0.417,2.304]$ m |
| Spatial gate + ICODE | +28 | -28 | $+0.639\,[0.448,0.806]$ m |
| Temporal gate + nominal | -5 | +5 | $-0.067\,[-0.265,0.144]$ m |

这些总体改善不能掩盖 56 次碰撞和明显的方向/速度分层失效。开发安全门优先于平均终点距离。

## 5. 失效机制

### 5.1 当前闭合速度不是目标速度估计

L30 门控对前、左、右三个扇区的最小距离做相邻时刻差分。移动物体跨越扇区或激光束时，最小点的身份会切换，因此该量不是同一障碍的物理速度。

反向横穿碰撞前 1 s 的“最大闭合速度”分层均值达到 seen $31.53\,\mathrm{m/s}$、unseen $29.14\,\mathrm{m/s}$，远超场景真实障碍速度。这是 beam/sector reassociation 产生的伪速度，证明当前估计器缺乏物理可解释性。

### 5.2 风险信号和控制器置信度被混为一体

56 个碰撞 episode 在碰撞时的门控系数全部为 1。当前实现将“闭合风险高”解释为“应完全使用 RL prior”，但该 RL policy 主要由静态障碍数据训练，输入也只有当前帧 LaserScan，无法从单帧判断障碍运动方向。

快速横穿中，碰撞前 1 s 的闭合速度均值约为 $0.38--0.40\,\mathrm{m/s}$，属于真实风险；但门控饱和后，RL prior 没有可靠的动态避让能力。也就是说，即使风险检测正确，控制器选择逻辑仍不成立。

### 5.3 scan_guard 不能替代动态预测

反向横穿碰撞前 1 s 的 safety override 比例约为 0.63，线速度已降至约 $0.08\,\mathrm{m/s}$；障碍中心最小距离约 $0.44\,\mathrm{m}$，与车体和障碍半径之和接近。机器人即使停止前进，侧向运动障碍仍可能撞上车体。现有 scan_guard 的职责是最终局部安全仲裁，而不是动态目标跟踪和未来占据预测。

## 6. 对研究方向的影响

本轮提供了有价值的可证伪结果：

1. 支持“空间复杂度门控不足”的判断，因为时间门控相对空间门控仍有 +28 次净成功；
2. 反驳“风险越高就越应启用当前 RL prior”的简单规则；
3. 反驳“单帧 LaserScan 足以解决方向不同的动态障碍”的隐含假设；
4. 表明 ICODE 的预测优势不能自动转化为控制安全。在相同时间门控下，本轮 ICODE 相对 nominal 没有非劣证据；该结果只适用于当前 policy、动态场景和 checkpoint，不应泛化为 ICODE 普遍无效。

因此，论文主张应从“risk-triggered RL”收紧为“hazard estimation 与 policy competence confidence 分离的跨层调控”。这是比调阈值更实质的结构修正。

## 7. 下一开发阶段（L32）

L32 不在 L31 数据上重新调参后复报通过，而建立新的预注册开发集。最低要求为：

1. **时间可观测性**：RL observation 增加固定长度 scan history 或鲁棒 scan-flow 特征，使方向和闭合趋势可辨识；
2. **鲁棒运动特征**：用多 beam 支持、速度上限与连续性检查替代扇区单最小值差分，显式记录无效匹配；
3. **两信号分离**：hazard score 描述环境风险，competence confidence 决定 RL 是否可信，禁止用 `max(risk, alpha)` 直接把高风险等同于高 RL 权重；
4. **共享动态安全基线**：若加入动态占据预测或 TTC safety shield，应对所有方法一致启用，作为工程安全层而非偷偷只帮助提出方法；
5. **动态数据重训**：RL 必须在方向、速度、相位随机化的动态障碍中训练，并保留纯静态场景回归；
6. **全新种子与变体**：L31 数据只用于失效分析，L32 使用新的开发 episode seeds；`20283106--20283120` 继续封存。
